# Проверка локального Web3-пути — 11 сентября 2026

## Результат

Стенд запущен локально. Это проверка существующего аватара Robert с одобренными версиями для трёх проектов, а не подтверждение готовности публичного self-service для любых моделей.

- В браузере пройдены каталог → цена коллекции → 3D-превью Robert. Метаданные загрузились, цена 0.001 test SOL, на момент проверки выпущено 2 из 5 экземпляров.
- Форма публикации принимает реальный VRM и показывает PREVIEW READY. Новая публикация и новая покупка через Phantom в этом прогоне не подписывались: встроенный браузер не имеет Phantom.
- Space: подключение тестового покупателя по коду, выбор Robert, статус Equipped.
- Mirror Simulator: подключение того же покупателя по коду, загрузка одобренного USDZ, выбор для камеры, 3D-превью с подписью «Из вашего кошелька · Devnet». AR-трекинг на физическом iPhone не проверялся.
- Omoba: тестовый покупатель успешно подключён; клиент получил одну одобренную покупку и первый снимок настоящего UDP-сервера. Новый визуальный выбор платного Robert в игре не подтверждён: средство UI-автоматизации не распознаёт окно Bevy. Историческое визуальное доказательство отдельно в VERIFICATION.md.
- После перезапуска: 7 live HTTP-проверок прошли на настоящей существующей Devnet-покупке: владение, отказ чужому кошельку, привязка сессии к проекту, одноразовые билеты и точные байты всех трёх моделей. См. web3-alpha-http-20260911.json.
- TypeScript, 44 теста покупки/публикации/метаданных/маршрутов, production-сборка магазина и Debug-сборка Mirror прошли. git diff --check без ошибок.

## Исправления

В магазине показано объяснение, если выбранный кошелёк отсутствует в браузере. Уточнены инструкции подключения нативных клиентов. В явном Web3 Debug-режиме Mirror скрыты Studio, отдельный магазин и отдельный identity-only вход; осталась «Мои аватары · Devnet». Поведение обычной App Store-сборки сохранено. Сайт пересобран с перезапуском сервера, чтобы избежать старых ссылок на CSS.

## Пройти завтра

1. Оставить IPFS Desktop включённым. Открыть http://127.0.0.1:5190/passport во внешнем браузере с Phantom и включённым Devnet. Подключить свой кошелёк.
2. View price & buy → проверить Robert, 0.001 SOL и три значка поддержки → купить один экземпляр. Нужен запас test SOL также на сетевые расходы. В коллекции всего 5 экземпляров; не повторять оплату при неизвестном результате, сначала проверить кошелёк/подтверждение.
3. Вернуться в My avatars, подтвердить вход сообщением и проверить Robert. Сообщение входа не является транзакцией покупки.
4. Открыть http://127.0.0.1:7110/space/1 → Purchased avatars → Connect through Avatar Store. Подтвердить код тем же кошельком → выбрать Robert → дождаться Equipped.
5. Mirror в симуляторе: каталог аватаров → Мои аватары · Devnet → подключить кошелёк → открыть ссылку с кодом во внешнем браузере → подтвердить → Выбрать для камеры.
6. Из solana-avatars выполнить `node scripts/avatar-roundtrip.mjs --omoba`. Открыть выданную ссылку с кодом, подтвердить тем же кошельком. В игре выбрать купленного Robert и войти в матч. Именно этот визуальный шаг остаётся перепроверить.
7. Для проверки автора открыть Publish, выбрать свой VRM, задать имя, supply и цену. Публикация новой коллекции не означает автоматическую поддержку всех игр: конвертация и одобрение версий пока операторские, описаны в README.

## Если стенд остановлен

Из `/Users/wotori/git/ekza/solana-avatars`:

```sh
EKZA_PASSPORT_LOCAL_IPFS=1 node scripts/avatar-roundtrip.mjs --serve
```

Команда занимает терминал. При занятых портах не запускать второй экземпляр. Для пересборки сначала остановить этот процесс Ctrl+C, затем `cd app && npm run build`, вернуться в родительскую папку и запустить стенд снова. Перезапуск сбрасывает временные сессии: приложения нужно подключить заново.

Mirror Debug после запуска симулятора:

```sh
xcrun simctl launch booted com.wotori.ekzamirror --ekza-passport-demo -EkzaPassportOrigin http://127.0.0.1:5190
```

## Границы готовности

Публичного деплоя нет. Текущая архитектура Passport требует одного долгоживущего Node-процесса. Realtime-backend Space отдельно не запущен; этот прогон проверяет применение аватара, а не мультиплеер Space. Локальный IPFS помогает текущим метаданным, но не доказывает доступность публичного IPFS для внешних тестеров. Публикация и покупка с личным Phantom, визуальное применение в Omoba и физический iPhone остаются явными пунктами приёмки.
